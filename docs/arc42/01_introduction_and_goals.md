## 1.1 需求概述

CelloCoach 是給大提琴學生在家練琴用的**即時音準與節奏教練**。它讀進 MusicXML 樂譜，用裝置麥克風聆聽演奏，即時跟譜面比對，練習結束後給出一份詳細的逐音報告。

核心理念（承襲原始 README）：市面上的調音器反應太慢，不適合在拉曲子時對音準。「拉一個音 → 看調音器 → 修正 → 再拉一個音」的循環和真實練琴流程脫節。直接拿整首樂譜跟演奏即時比對，才能一次抓出整首曲子裡的問題模式（哪幾顆音常拉錯、哪根弦容易跑掉）。

本專案是把上述能力以**原生 Android App** 重新實作。原始版本是 Flask 後端 + 瀏覽器前端的 Web 系統；Android 版把所有運算搬進 App 內，使用流程更順、不需任何網路設定。

### 要解決的核心問題（來自原始 README）

| 編號 | 問題 | 期望結果 |
|---|---|---|
| G1 | 調音器反應太慢、與練琴流程脫節 | 跟著真實樂譜即時比對，不打斷演奏 |
| G2 | 缺乏即時音準＋節奏回饋 | 每顆音當下顯示「應拉 vs 你拉」、cents 偏差、good/close/off/wrong 狀態 |
| G3 | 沒有整首練習的結構化檢討 | 結束後給總分、對音 X/Y、平均音準、逐音明細，外加自動診斷 |
| G4 | 評分硬綁 A=440，誤把琴的走音當成拉錯 | 開練前拉四條空弦做**逐弦校正**，以實際琴音為基準；校正自動存檔下次套用 |
| G5 | 死綁時間軸跟不上學生 | DTW 風格 score follower：拉慢、拉快、跳音、暫停都跟得上（單向） |
| G6 | 沒有起拍預備 | 依樂譜 BPM 的節拍器，開始前 4 拍 click 倒數 |
| G7（Android 特有） | 原 Web 版在 LAN／行動裝置上的 HTTPS／secure-context／連線設定痛點 | 原生 App，無瀏覽器、無 server、無網路設定，麥克風權限一次授權即可 |

> G7 是本次平台轉換最大的附帶價值。原 README 用整段篇幅說明 `--ssl`、self-signed 憑證警告、`chrome://flags/#unsafely-treat-insecure-origin-as-secure` 白名單、reverse proxy 終結 TLS 等繞道方法——這些在原生 App 下全部消失。詳見 [3. 系統脈絡與範圍](03_context_and_scope.md)。

## 1.2 品質目標

依重要性排序的前五大品質目標：

| 優先 | 品質屬性 | 具體目標 | 對應問題 |
|---|---|---|---|
| 1 | 即時性（效能） | 麥克風→音高偵測→回饋的端到端延遲低到足以在演奏中對音（偵測 ~20Hz、UI tick ~50ms） | G1, G2 |
| 2 | 正確性 | 音高偵測、跟譜、計分、診斷與 Python 參考實作行為對齊（逐行移植，常數一致） | G2, G3, G5 |
| 3 | 易用性 | 安裝即用，零網路設定，一次麥克風授權；不再需要 HTTPS／憑證／IP 白名單 | G7 |
| 4 | 可離線性 | 完全 on-device、離線運作，無後端、無外連 | G7 |
| 5 | 可測試性 | 核心演算法可在 JVM 純單元測試；UI 可用 Robolectric + 假麥克風在 devcontainer 內免 emulator 做 e2e 螢幕驗證 | 全部 |

## 1.3 利害關係人

| 角色 | 關注點 |
|---|---|
| 大提琴學生（主要使用者） | 音準回饋準不準、跟譜跟不跟得上、報告看不看得懂、好不好上手 |
| 老師／家長 | 練習報告能否點出反覆出錯的音與系統性偏移 |
| 開發者（並行 agent） | 模組簽章穩定可整合（見 `CONTRACTS.md`）、可在 devcontainer 內建置與測試 |
| 維護者 | 與 Python 參考實作對齊、離線無依賴、相依套件鎖定在 `app/build.gradle.kts` |
